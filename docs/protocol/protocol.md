# Протокол роботи з пристроєм Oscill (OBEX)

Обмін даними з пристроєм Oscill здійснюється за допомогою протоколу OBEX, доповненого приватними заголовками. Oscill працює як сервер, Comp (ПК/PDA/смартфон) — як клієнт. Протокол забезпечує сумісність різних моделей/версій ПЗ шляхом:
- читання незмінних властивостей (Properties);
- читання/запису регістрів (Registers) із підтвердженням фактичних значень;
- виконання команд (Commands) з поверненням результатів.

Транспорт: RS232/USB/Serial IR/IRDA/Bluetooth (SPP/Object Push).

## 1. Спеціальні заголовки Oscill

Використовуються стандартні OBEX-заголовки і розширення:

- 0x70 (Byte Sequence): ім’я властивості (ASCII), тільки GET.
- 0x71 (Byte Sequence): ім’я регістра (ASCII), GET/PUT.
- 0x72 (Byte Sequence): команда (ASCII), наприклад "D", "C".
- 0x49 (Byte Sequence): тіло об’єкта або остання частина тіла (результати оцифровки).
- 0xB1 (One Byte): однобайтове значення.
- 0xF0 (Four Byte): двобайтове значення, передається 4 байтами (big-endian; значущі 2 байти — старші/молодші згідно big-endian; знаковість — за семантикою поля).
- 0xF1 (Four Byte): чотирибайтове значення (big-endian) або 4 ASCII-байти (для рядкових властивостей, наприклад версії/ідентифікатори).
- 0xB0 (One Byte): контрольна сума пакета; сума всіх байтів пакета (включно з 0xB0) mod 256 = 0.

Зауваження щодо кодування:
- Числа — big-endian.
- 2-байтові знакові поля — two’s complement усередині 0xF0.
- Імена властивостей/регістрів/команд — ASCII у верхньому регістрі.

## 2. Типи пакетів OBEX

Request (клієнт → сервер):
- 0x80 Connect, 0x81 Disconnect
- 0x02/0x82 Put, 0x03/0x83 Get
- 0xFF Abort
- 0x91 Oscill_speed (швидкість = 1842000 / коеф.)
- 0x92 Oscill_resend (повтор останнього Response)

Response (сервер → клієнт):
- 0x10/0x90 Continue — наступна порція довгих даних (Get продовжувати)
- 0x20/0xA0 Success — виконано
- 0x24/0xA4 No Content — даних нема
- 0x40/0xC0 Bad Request — запит нерозпізнаний
- 0x51/0xD1 Not Implemented — відсутня функція
- 0xD0 Internal Server Error — помилка обробки (допустиме повторення запиту клієнтом)

## 3. Обмін властивостями/регістрами

Читання властивості (GET):
- Request: opcode=Get, 0x70="NAME", [необов’язково 0xB0]
- Response: Success/Continue + значення у 0xB1/0xF0/0xF1

Читання регістру (GET):
- Request: opcode=Get, 0x71="NAME"
- Response: Success/Continue + значення у 0xB1/0xF0/0xF1

Запис регістру (PUT):
- Request: opcode=Put, 0x71="NAME", 0xB1/0xF0/0xF1=VALUE
- Response: Success + фактичне встановлене значення у 0xB1/0xF0/0xF1
- Зауваження: читане значення може відрізнятися від записаного (квантування/обмеження/залежності).

Команди:
- Калібрування: PUT, 0x72="C" → Success
- Оцифровка: GET, 0x72="D" → Success/Continue з масивами у 0x49
- Зміна швидкості: opcode=0x91, payload=коефіцієнт (speed=1842000/coef)
- Повтор Response: opcode=0x92 (для корекції помилки під час приймання)

## 4. Властивості (Properties, read-only)

Системні:
- VNM (4B ASCII): ідентифікатор пристрою
- VSN (4B ASCII): серійний номер
- VHW (4B ASCII): версія HW
- VSW (4B ASCII): версія SW
- MCd (2B, u): тривалість машинного циклу за замовчуванням (крок 10 пс)
- MCl (2B, u): мінімальна тривалість машинного циклу (крок 10 пс)

Дискретизація:
- TOl (2B, u): мін. період однократної дискретизації (у MC*256)
- TOv (4B, bitset): карта швидких варіантів однократної дискретизації
- TMl (2B, u): мін. період стробоскопічної (RIS) (у MC*256)
- TMh (2B, u): макс. період стробоскопічної (RIS) (у MC*256)
- TPl (4B, u): мін. період паралельної/бескінченної (ROLL) без додаткової обробки
- QSh (2B, u): максимальний розмір вихідного масиву вибірок
- TCh (2B, u): максимальна кількість предвибірок
- TDl (4B, u): мінімальна затримка розгортки (у 12*MC)
- TDh (4B, u): максимальна затримка розгортки (у 12*MC)

Канал 1:
- V1h/V1l (2B, u): макс./мін. чутливість (В/діл, кванти)
- P1h/P1l (2B, s): діапазон зміщення (1/256 АЦП)
- D1m (2B, u): конструктивна затримка компаратора синхронізації (10 пс); залежить від S1/T1

Примітка: для інших каналів імена аналогічні (V2, P2, …) — якщо підтримується багатоканальність.

## 5. Регістри (Registers, read/write)

Системні:
- MC (2B, u): тривалість машинного циклу (10 пс)
- RT (1B, bits): тип запуску (авто/ждущий/вільний/нескінченно ждущий)
- TA (4B, u): макс. очікування синхронізації при авто-запуску (у 12*MC)
- TW (4B, u): макс. очікування синхронізації при ждущому запуску (у 12*MC)

Розгортка/дискретизація:
- TS (4B, u): період дискретизації (MC*256) — найвищий пріоритет
- RS (1B, bits): спосіб оцифровки (realtime/стробо/паралельна/ROLL)
- AP (1B, u): кількість проходів усереднення/пікового режиму (2^n - 1)
- AR (1B, u): мінімальна кількість проходів для однієї RIS-затримки
- QS (2B, u): кількість вибірок у масиві
- TD (4B, u): затримка розгортки (у 12*MC)
- TC (2B, u): центрування (вибірки до/після синхронізації)

Канал 1:
- O1 (1B, bits): HW-режим каналу (вхід/фільтри)
- V1 (2B, u): чутливість (впливає на діапазон P1)
- P1 (2B, s): зміщення вхідного діапазону АЦП
- M1 (1B, bits): SW-обробка вибірок (усереднення/піковий/звичайний)
- T1 (1B, bits): режим синхронізації (фронт/спад/гістерезис/ВЧ/НЧ)
- S1 (1B, u): рівень синхронізації (0..255)

Залежності (скорочено):
- TS впливає на RS, M1, TD
- RS впливає на TD, M1
- QS залежить від RS/TS/M1
- TC/TD залежать від RS/TS/QS
- V1 впливає на P1, P1h/P1l
- AP/AR впливають на QS/QSh
- RT визначає застосування TA або TW

## 6. Команди

- "C" (калібрування): PUT з 0x72="C" → Success.
- "D" (оцифровка): GET з 0x72="D" → Success із 0x49 (масиви) або Continue (ROLL/паралельна).

Режими (RS, коротко):
- Однократна (realtime)
- Стробоскопічна (RIS)
- Паралельна (передача під час оцифровки)
- Нескінченна (ROLL)

## 7. Формат результатів оцифровки (0x49)

Структура:
1) 2 байти: атрибути оцифровки (режим/джерело запуску/кількість каналів)
2) Для кожного каналу (1..N):
   - 2 байти: атрибути каналу (формат масиву)
   - 2 байти: розмір масиву (байт)
   - N байт: масив вибірок

Перший байт атрибутів оцифровки:
- біт0: 0 — однократна, 1 — стробоскопічна
- біт1: 0 — передача після, 1 — паралельна
- біт2: 0 — кінцева, 1 — нескінченна (ROLL)
- біти5..4: джерело запуску (00 TA, 01 спад, 10 фронт)
- біти7..6: кількість каналів (00 — 1, 01 — 2, 10 — 3, 11 — 4)

## 8. Корекція помилок

- Контрольна сума 0xB0 — опційно.
- Якщо сервер виявив помилку у Request → 0xD0; клієнт може один раз повторити Request.
- Якщо клієнт виявив помилку у Response → відправити 0x92 (Oscill_resend) один раз.
- Відсутність відповіді: повторити запит після захисного інтервалу.

## 9. Приклади потоків обміну

Читання властивості (наприклад, "MCd"):
- Get + 0x70="MCd" → Success з 0xF0 (2B-as-4B)

Запис регістру (наприклад, "TS"):
- Put + 0x71="TS" + 0xF1=value → Success з 0xF1=фактичне TS

Команда оцифровки:
- Get + 0x72="D" → Continue/Success з 0x49 (масиви). У ROLL — багаторазовий Continue; зупинка Abort.

## 10. Нотатки для реалізацій на інших мовах

- Використовуйте big-endian при кодуванні чисел для 0xF0/0xF1.
- Для 2-байтових знакових полів застосовуйте two’s complement (у 0xF0).
- 4-байтові “рядкові” властивості (VNM/VSN/VHW/VSW) — 4 ASCII-байти, повертаються у 0xF1 без перекодування.
- Довгі дані (оцифровка) передаються через 0x49 із можливими декількома Continue.
- Після запису регістру обов’язково перечитуйте значення та межі залежних властивостей (наприклад, після V1 — P1h/P1l).
