# Auto-Connect and Configuration Persistence

## Функціональність автопідключення при завантаженні сторінки

При відкритті веб-додатку автоматично виконується наступна послідовність дій:

### 1. Автопідключення до пристрою
```javascript
const connectResult = await this.api.connect();
```

- Викликається метод `connect()` без параметрів (auto-detect)
- Якщо пристрій знайдено - підключається
- Якщо вже підключено - повертає поточний статус

### 2. Відновлення збереженої конфігурації
```javascript
const savedConfig = this.loadSavedConfig();
if (savedConfig) {
  await this.api.applyConfig(savedConfig);
}
```

- Завантажує останню збережену конфігурацію з `localStorage`
- Застосовує її до пристрою
- Конфігурація включає:
  - Вертикальні налаштування (v_div, v_offset)
  - Горизонтальні налаштування (t_div, t_offset)
  - Налаштування тригера (trigger_level, trigger_slope, trigger_mode)
  - Режими обробки (sw_mode, sync_type)
  - Фільтри (filter_high, filter_low)
  - Тип входу (coupling)

### 3. Оновлення статусу UI
```javascript
const status = await this.api.getStatus();
this.updateStatus(status);
```

- Отримує поточний статус пристрою
- Оновлює інтерфейс користувача

### 4. Автоматичний запуск збору даних
```javascript
await this.api.start();
this.isRunning = true;
this.controlPanel.setAcquisitionState('run');
```

- Автоматично запускає збір даних
- Оновлює стан кнопки Run/Stop в UI

### 5. Запуск опитування фреймів
```javascript
this.startPolling();
```

- Запускає циклічне опитування для отримання нових фреймів
- Графік починає відображати дані одразу

## Збереження конфігурації

### Автоматичне збереження при зміні
Кожна зміна конфігурації автоматично зберігається в `localStorage`:

```javascript
async onConfigChange(changes) {
  const response = await this.api.applyConfig(changes);
  if (response.config) {
    this.saveConfig(changes);  // ← Автозбереження
  }
}
```

### Що зберігається
Зберігається тільки те, що користувач змінив:
- Зміни вертикальної чутливості
- Зміни горизонтальної розгортки
- Налаштування тригера
- Зміщення по осях
- Режими обробки
- Стан фільтрів

### Формат збереження
```javascript
// localStorage key: 'oscill_config'
{
  "v_div": {"v": 500, "u": "mV"},
  "t_div": {"v": 10, "u": "ms"},
  "trigger_level": 128,
  "trigger_slope": "Rising",
  "coupling": "DC",
  "sw_mode": "NORMAL",
  ...
}
```

## Обробка помилок

### Якщо пристрій не знайдено
```javascript
catch (e) {
  console.error('[App] Auto-connect failed:', e);
  // Показується статус "disconnected"
  // Користувач може підключитись вручну
}
```

### Якщо не вдалося застосувати збережену конфігурацію
```javascript
try {
  await this.api.applyConfig(savedConfig);
} catch (e) {
  console.warn('[App] Failed to apply saved config:', e);
  // Продовжується з дефолтною конфігурацією
}
```

### Якщо не вдалося запустити збір даних
```javascript
await this.api.start();
// При помилці відображається в консолі
// UI залишається в стані "stop"
```

## Користувацький сценарій

### Перше відкриття
1. ✅ Підключається до пристрою автоматично
2. ✅ Використовує дефолтну конфігурацію
3. ✅ Запускає збір даних
4. ✅ Показує сигнал на графіку

### Наступні відкриття
1. ✅ Підключається до пристрою автоматично
2. ✅ Відновлює останні налаштування користувача
3. ✅ Запускає збір даних
4. ✅ Показує сигнал з попередніми налаштуваннями

### Зміна налаштувань
1. Користувач змінює параметр (наприклад, v_div)
2. ✅ Зміна застосовується до пристрою
3. ✅ Зміна автоматично зберігається в localStorage
4. При наступному відкритті - відновлюється

## API методи

### В `app.js`

#### `autoConnectAndStart()`
Головний метод автоініціалізації. Викликається з `init()`.

#### `loadSavedConfig()`
Завантажує конфігурацію з `localStorage`.
```javascript
const config = this.loadSavedConfig();
// Returns: object | null
```

#### `saveConfig(changes)`
Зберігає зміни конфігурації в `localStorage`.
```javascript
this.saveConfig({
  v_div: {v: 500, u: "mV"}
});
```

## Налаштування

### Відключення автопідключення
Якщо потрібно відключити автопідключення, закоментуйте виклик в `init()`:

```javascript
async init() {
  // ...
  // await this.autoConnectAndStart(); // ← Закоментувати
}
```

### Очищення збереженої конфігурації
Через консоль браузера:
```javascript
localStorage.removeItem('oscill_config');
```

Або додати кнопку "Reset to defaults" в UI.

---

## Переваги

1. **Зручність** - не потрібно щоразу налаштовувати
2. **Швидкість** - додаток готовий до роботи одразу
3. **Персоналізація** - зберігає налаштування користувача
4. **Надійність** - обробляє помилки gracefully

## Технічні деталі

### localStorage
- **Key**: `oscill_config`
- **Format**: JSON string
- **Size**: ~1-5 KB (залежить від кількості налаштувань)
- **Lifetime**: Поки користувач не очистить браузер

### Послідовність викликів API
1. `POST /api/connect` - підключення
2. `POST /api/config` - застосування конфігурації (якщо є збережена)
3. `GET /api/status` - отримання статусу
4. `POST /api/start` - запуск збору
5. `GET /api/frames` - циклічне опитування (кожні 100ms)

### Продуктивність
- Час ініціалізації: ~0.5-1.5 секунди
- Не блокує UI
- Всі операції асинхронні
