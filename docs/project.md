# Oscill2: клієнтський контролер Oscill через OBEX

Проєкт надає клієнтську реалізацію протоколу обміну з осцилографом Oscill поверх OBEX (Object Exchange). Основна мета — уніфікований інтерфейс для читання властивостей, керування регістрами, виконання команд (калібрування, оцифровка), а також отримання даних вибірок з пристрою.

## Архітектура

- obex/
  - Транспорт OBEX (Connect/Disconnect/Put/Get/Abort), повтори, контроль довжини/суми.
  - ClientSession — керує сесією, швидкістю лінку, передачею пакетів/заголовків.
- controller/
  - Oscill — високорівневий контролер пристрою (виклики за іменами властивостей/регістрів/команд).
  - BaseOscillController — спільна логіка перетворень типів і викликів ClientSession.
- types/
  - BitSet — робота з побітними регістрами.
- utils/
  - Log — журналювання.

Ціль: API, яке стабільно працює з різними ревізіями прошивки/заліза Oscill, через механізм властивостей (read-only), регістрів (read/write) і команд.

## Ключові можливості

- Запит властивостей (наприклад, діапазони, версії, системні обмеження).
- Налаштування регістрів (TS, RS, V1, P1, TD, QS тощо).
- Команди:
  - "C" — калібрування.
  - "D" — запуск оцифровки та отримання вибірок (включно з ROLL/паралельною передачею).
- Корекція помилок: контрольна сума 0xB0, повтор Response (0x92), захисні інтервали.
- Зміна швидкості лінку: 0x91 (speed = 1842000 / coef).

## Протоколна модель

- Властивості: тільки GET, заголовок 0x70 з ASCII-іменем, значення повертається через 0xB1/0xF0/0xF1.
- Регістри: GET/PUT, заголовок 0x71 з ASCII-іменем, при PUT значення передається в 0xB1/0xF0/0xF1.
- Команди: заголовок 0x72 з ASCII-ідентифікатором ("C", "D").
- Формати значень:
  - 0xB1 — 1 байт.
  - 0xF0 — 2 байти, передані як 4 (big-endian, знаковість визначається семантикою регістру/властивості).
  - 0xF1 — 4 байти (big-endian або 4-ASCII-байти для версій/ідентифікаторів).

Деталі й повні списки властивостей/регістрів див. у docs/protocol/protocol.md.

## Типовий сценарій використання

1) Встановити лінк (RS232/USB/BT/IRDA) і підняти OBEX-сесію (Connect).
2) Прочитати системні властивості (VNM, VSN, VHW, VSW, MCd/MCl тощо).
3) Задати ключові регістри: MC, TS, RS, M1, QS, TC/TD, T1/S1, AP/AR/RT/TA/TW.
4) Команда "C" (за потреби) — калібрування.
5) Команда "D" — оцифровка; читати результат з 0x49 (Continue/Success).
6) При ROLL — завершити Abort.

## Портованість (інші мови)

- Потрібна мінімальна OBEX-реалізація: формування пакетів, передача/парсинг заголовків, керування потоковими даними (Continue).
- Реалізувати мапінг:
  - Name headers: 0x70 (property), 0x71 (register), 0x72 (command) — ASCII-імена (V1, TS, "D" тощо).
  - Value headers: 0xB1 (1B), 0xF0 (2B-as-4B), 0xF1 (4B).
  - Body: 0x49 — дані оцифровки/довгі тіла об’єктів.
  - Checksum: 0xB0 — необов’язковий (сума пакета mod 256 = 0).
- Endianness: big-endian для чисел; 2-байтові знакові величини — two’s complement.

## Побудова та тестування

- Зібрати застосунок (Android/Java) і під’єднатися до реального пристрою або симулятора OBEX.
- Перевірити цикли:
  - Connect → Get(VNM/VSN/…) → Put(MC/TS/… ) → Get(read-back) → Get("D") → читання 0x49.
  - Перевірка помилок: зіпсувати пакет, перевірити 0xD0 та повтор 0x92.
