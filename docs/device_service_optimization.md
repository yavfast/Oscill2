# Оптимізація DeviceService - Кешування конфігурації та Executor Pool

## Зміни

### 1. Кешування конфігурації
- **Додано `_cached_config`**: Зберігає останню конфігурацію в пам'яті
- **Додано `_config_lock`**: Thread-safe доступ до кешу
- **Методи `_update_cached_config()` та `_get_cached_config()`**: Безпечне оновлення та читання кешу
- **`get_status()` тепер не запитує девайс**: Повертає кешовану конфігурацію миттєво

### 2. Однопоточний Executor Pool
- **`_device_executor`**: ThreadPoolExecutor з max_workers=1 для серіалізації команд
- **`_device_timeout`**: Таймаут 5 секунд для всіх операцій з девайсом
- **Всі запити до девайсу через executor**: connect, disconnect, apply_config

### 3. Переробка публічних методів

#### `connect(port, baud)` → executor
- Внутрішня реалізація: `_connect_internal()`
- Публічний метод виконує через executor з таймаутом
- Після підключення кешує конфігурацію

#### `disconnect()` → executor  
- Внутрішня реалізація: `_disconnect_internal()`
- Публічний метод виконує через executor з таймаутом
- Очищає кеш конфігурації

#### `apply_config(changes)` → executor
- Внутрішня реалізація: `_apply_config_internal()`
- Публічний метод виконує через executor з таймаутом
- Оновлює кеш після успішної зміни

#### `get_status()` → НЕ блокує, повертає кеш
- Читає `_cached_config` без звернення до девайсу
- Швидкість: < 0.001 секунди замість ~0.1-0.5 секунди
- Ідеально для частих запитів від UI

### 4. Додаткові методи
- **`shutdown()`**: Коректне завершення роботи з очищенням ресурсів

## Переваги

1. **Продуктивність**: `get_status()` в 100-500 разів швидше
2. **Безпека**: Всі запити до девайсу серіалізовані через executor
3. **Таймаути**: Захист від зависань (5 сек таймаут)
4. **Кешування**: Конфігурація оновлюється тільки при реальних змінах
5. **Thread-safe**: Всі операції з кешем захищені локами

## Поведінка

### До змін:
```python
# get_status() запитував девайс кожного разу
status = service.get_status()  # ~0.1-0.5 секунди
```

### Після змін:
```python
# get_status() читає з кешу
status = service.get_status()  # < 0.001 секунди

# Зміни конфігурації через executor
service.apply_config({'v_div': {'v': 500, 'u': 'mV'}})  # ~0.1-0.5 сек, але з таймаутом

# Всі команди до девайсу серіалізовані
service.connect()      # Через executor
service.disconnect()   # Через executor
```

## Тестування

Запустіть тестовий скрипт:
```bash
python3 test_device_service.py
```

Тести перевіряють:
1. Статус при відключенні
2. Підключення до девайсу
3. Швидкість get_status (має бути < 0.001s)
4. 100 послідовних викликів get_status (< 0.5s загалом)
5. Отримання фреймів
6. Зміну конфігурації
7. Відключення

## Сумісність

- Всі існуючі API endpoints в `main.py` працюють без змін
- Backwards compatible з попередньою реалізацією
- Acquisition loop (`_acq_loop`) працює як і раніше, але оновлює кеш
